## Oracle types

- **differential**: the same request is sent to PX4 directly (GCS link, no
  proxy) and through the proxy. Directly, PX4 visibly reacts; through the
  proxy it does not within the same window, and the proxy counts the frame as
  dropped. A control sends the same frame straight to the link behind the
  proxy (bypassing it) and sees the reaction come back through the proxy, so
  the silence is the proxy's drop and not a link that would not have reacted.
  For allowed traffic, "differential" means PX4's reaction through the proxy
  is the positive evidence.
- **egress-only**: PX4 SITL shows no reaction to the message, so only the
  proxy's egress is checked: the frame is counted as an SR-011 drop and is not
  among the frames the proxy sent to PX4 (the proxy's `on_forward` hook,
  `forward_tap`), and an allowlisted frame sent after it is. This shows the
  proxy did not send it; it shows nothing about what PX4 would do with it.
- **unit**: `pytest -m "not sitl"`, no PX4 (classifier, token bucket, command
  log, proxy over loopback sockets with a fake FC socket).

What the threat rows do **not** cover:

- THR-003 also names parameter writes; `PARAM_SET` is on the proposed
  allowlist, so the proxy forwards it. CC-originated traffic and the USB
  maintenance link are not filtered (the threat's stated residual).
- THR-004: the log attributes a command to a peer by source IP. That is only
  bound to a WireGuard key under the assumption below; the shared signing key
  itself still cannot be attributed.
- THR-005: a fully compromised CC can bypass the rate limit (the threat's
  stated residual).
- THR-050/051: for COLLISION and RADIO_STATUS the evidence is that the proxy
  does not send them, not that PX4 is unaffected by them.

## Assumptions

1. **Peer identity is the source IP.** The proxy maps a packet's source IP to a
   peer through `policy.yaml` `peers`, which mirrors **WireGuard AllowedIPs**:
   in the intended deployment WireGuard only accepts an inner source IP inside
   the sending peer's AllowedIPs, so the IP is bound to the peer's key.
2. **No real tunnels.** No WireGuard runs in these tests; the binding in (1) is
   assumed, not enforced, and all test traffic comes from loopback as the
   `cc-local` peer.
3. **The allowlists, rates and peer map are proposed** (`policy.yaml`
   `status: proposed`), not approved. Only the six SR-011 exclusions come from
   P1. The owner has to approve them before any result here counts against the
   approved values that SR-011 and SR-012 refer to.
4. **SITL stands in for the FC.** The FC is PX4 SITL with the SIH model on
   UDP links, not flight hardware on a UART.
5. **Uplink only.** The proxy filters GCS to FC traffic. FC to GCS traffic is
   relayed unfiltered.
